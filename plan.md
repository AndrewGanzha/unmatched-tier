# План дальнейшей работы по Unmatched Tier

## 1. Текущее состояние проекта

На данный момент в проекте уже собран рабочий базовый вертикальный срез для режима `1v1`:

- есть приложение на `Next.js + TypeScript + Prisma + SQLite`
- настроена доменная модель для пользователей, игроков, героев, матчей, рейтинга и турниров
- реализован вход по email/password
- есть роли `ADMIN` и `PLAYER`
- администратор может создавать игроков
- администратор может создавать героев
- администратор может создавать матч `1v1`
- система может автоматически назначать героев по `RuleConfig`
- матч можно перевести в `READY`
- можно зафиксировать результат матча
- после результата пересчитывается рейтинг `Elo`
- есть страницы leaderboard, history, players, heroes, match details

При этом проект еще не готов к нормальному рабочему использованию: есть технические долги, не завершены `2v2` и турниры, нет тестового покрытия, сиды неполные, а production build сейчас не проходит.

## 2. Главная цель следующего этапа

Довести текущий MVP до стабильного состояния, чтобы система:

- уверенно собиралась и запускалась без ручных правок
- имела полный и проверенный сценарий `1v1`
- имела нормальные стартовые данные
- была подготовлена к безопасному расширению под `2v2` и турниры

## 3. Что осталось сделать

### Этап 1. Стабилизация текущего состояния

Сначала нужно убрать базовые технические проблемы, иначе дальнейшая разработка будет дорогой и ломкой.

Нужно:

- починить `npm run build`
- исправить конфиг ESLint
- решить проблему с типами `bcryptjs`
- проверить, нет ли других скрытых type/runtime ошибок
- привести кодировку текстов в порядок, чтобы русский текст не был поврежден
- убрать или аккуратно зафиксировать оставшиеся артефакты старого шаблона/макета
- проверить, что локальная БД и сиды не расходятся с текущей схемой

Результат этапа:

- проект стабильно собирается
- репозиторий не содержит случайного мусора
- интерфейс и тексты отображаются корректно

### Этап 2. Доведение сценария `1v1` до законченного MVP

Сейчас `1v1` уже работает, но его нужно довести до состояния, в котором сценарий не выглядит “черновиком”.

Нужно:

- проверить и усилить валидацию server actions
- проверить все ошибки и пограничные состояния в сценарии создания матча
- улучшить UX страниц `new match`, `match details`, `players`, `heroes`
- сделать более явные статусы и сообщения об ошибках
- проверить, что повторная отправка формы не ломает данные
- проверить, что матч нельзя повторно зарейтить
- проверить, что результат нельзя записать для некорректной стороны
- убедиться, что пересчет рейтинга консистентен для всех участников
- добавить недостающие revalidate/redirect сценарии там, где это действительно нужно

Результат этапа:

- `1v1` становится полноценным рабочим сценарием
- администратор может использовать систему без ручных обходов и “знания внутренних ограничений”

### Этап 3. Нормальные стартовые данные и админские настройки

Сейчас схема уже готова для правил и каталога героев, но фактическое наполнение слабое.

Нужно:

- заполнить `prisma/seed.ts` реальным списком героев Unmatched
- выровнять tier и `powerScore`
- проверить диапазоны `RuleConfig` на реалистичность
- определить стартовый набор admin/player пользователей для локальной разработки
- описать, какие данные обязательны для первого запуска
- при необходимости добавить страницу просмотра или редактирования `RuleConfig`

Результат этапа:

- проект можно развернуть и сразу использовать на реальных данных
- подбор героев начинает работать не на пустом каталоге, а на реальном пуле

### Этап 4. Тесты на ядро доменной логики

Сейчас это самый заметный пробел. Без тестов любые изменения в матчах и рейтинге будут рискованными.

Нужно:

- добавить unit-тесты для `Elo`
- добавить unit-тесты для логики выбора победителя и пересчета результатов матча
- добавить unit-тесты для логики автоподбора героев
- проверить граничные случаи rule-based назначения героев
- добавить интеграционный тест на сценарий:
  `создание 1v1 -> назначение героев -> READY -> результат -> пересчет рейтинга`
- проверить права доступа к admin-only действиям

Результат этапа:

- доменная логика покрыта тестами
- можно безопаснее рефакторить матчевый и рейтинговый слой

### Этап 5. Расширение модели и UI под `2v2`

Схема БД под `2v2` уже предусмотрена, но реальный продуктовый поток пока не реализован.

Нужно:

- спроектировать окончательный UX создания `2v2` матча
- реализовать server action для создания `2v2`
- корректно формировать две стороны по два игрока
- определить формулу командного рейтинга для расчета ожидаемого результата
- адаптировать логику автоподбора героев для команд
- проверить, что в одной игре не выдаются конфликтующие назначения
- адаптировать страницу матча и историю матчей под `2v2`
- проверить, как отображается рейтинг каждого игрока после командного матча

Результат этапа:

- `2v2` становится реальным поддерживаемым режимом, а не только полем в схеме

### Этап 6. Турнирный модуль

Нужно:

- добавить участников турнира

- отобразить турнирное состояние в UI
- продумать, какие действия админ может делать вручную, если нужно скорректировать сетку

Результат этапа:

- турнирный модуль становится рабочей частью приложения

### Этап 7. Улучшение API и интеграционного слоя

### Этап 8. Доработка безопасности и целостности данных

До релиза надо отдельно пройтись по рискам безопасности и консистентности.

Нужно:

Результат этапа:

### Этап 9. Финальная полировка MVP

Когда функциональность будет собрана, останется привести продукт к ровному виду.

Нужно:

Результат этапа:

## 4. Приоритеты

Если идти прагматично, порядок должен быть таким:

1. починить сборку и стабилизировать текущую базу
2. довести `1v1` до надежного MVP
3. добавить реальные сиды и настройки правил
4. закрыть тестами доменную логику
5. реализовать `2v2`
6. реализовать турниры
7. добить безопасность, API и финальную полировку

## 5. Критерии готовности MVP

Можно считать MVP готовым, когда выполняются все условия:

- проект собирается без ошибок
- есть понятный сценарий первого запуска
- есть реальный seed героев и admin-пользователь
- `1v1` проходит полный цикл без ручных исправлений
- рейтинг корректно меняется и отображается в UI
- история матчей и профиль игрока показывают согласованные данные
- ключевая доменная логика покрыта тестами
- роли и ограничения доступа работают предсказуемо

## 6. Что не обязательно делать прямо сейчас

Пока можно не тащить в ближайший этап:

- сезонную систему рейтинга
- баны персонажей
- сложные турнирные форматы кроме `single elimination`
- публичный пользовательский кабинет с отдельным UX для обычных игроков
- богатую аналитику по героям и матчапам
- разделение frontend/backend на разные приложения

## 7. Следующий практический шаг

Следующим шагом разумно заняться не новым функционалом, а стабилизацией базы:

1. починить `build`
2. исправить кодировки и тексты
3. проверить текущий `1v1` flow целиком
4. после этого уже переходить к тестам и расширению фич
