# Unmatched Tier

Административное веб-приложение для локального ведения игроков, героев, матчей и рейтинга по `Unmatched`.

Сейчас проект ориентирован на локальный запуск с `Next.js`, `Prisma` и `SQLite`.

## Возможности

- учёт игроков и их текущего рейтинга
- каталог героев с `tier`, типом боя и `power score`
- создание матчей `1v1`
- автоматическое назначение героев
- фиксация результата матча и пересчёт рейтинга
- таблица лидеров и история матчей
- вход администратора через seeded-аккаунт

## Быстрый старт

1. Установить зависимости:

```bash
npm install
```

2. Создать `.env` на основе примера:

```bash
copy .env.example .env
```

3. Заполнить переменные окружения.

Минимальный рабочий пример:

```env
DATABASE_URL="file:./dev.db"
SEED_ADMIN_EMAIL="admin@example.com"
SEED_ADMIN_PASSWORD="change-me-please"
```

4. Подготовить базу и стартовые данные:

```bash
npm run db:push
npm run db:seed
```

5. Запустить приложение:

```bash
npm run dev
```

После запуска приложение будет доступно на `http://localhost:3000`.

## Первый вход

1. Открой `http://localhost:3000/login`.
2. Войди под `SEED_ADMIN_EMAIL` и `SEED_ADMIN_PASSWORD`.
3. После входа будет доступна административная панель.

## Переменные окружения

### Обязательные

- `DATABASE_URL` — путь к SQLite базе, по умолчанию проект рассчитан на `file:./dev.db`

### Опциональные, но рекомендуемые

- `SEED_ADMIN_EMAIL` — email администратора, который будет создан или обновлён при `npm run db:seed`
- `SEED_ADMIN_PASSWORD` — пароль администратора для локального входа

Если `SEED_ADMIN_EMAIL` и `SEED_ADMIN_PASSWORD` не заданы, seed пропустит создание администратора.

## Что делает seed

Команда `npm run db:seed`:

- создаёт или обновляет администратора
- загружает стартовый список героев
- загружает стартовые `RuleConfig` для матчмейкинга и подбора силы

Seed написан идемпотентно: повторный запуск обновляет существующие записи, а не только создаёт новые.

## Основной сценарий использования

1. Создать или проверить игроков в разделе `Players`.
2. Проверить каталог героев в разделе `Heroes`.
3. Создать матч в разделе `New Match`.
4. Назначить героям стороны.
5. Перевести матч в `READY`.
6. Зафиксировать победителя.
7. Проверить изменения в `Leaderboard` и `History`.

## API и служебные маршруты

- `GET /api/health` — простой healthcheck
- `GET /api/leaderboard` — данные таблицы лидеров
- `GET /api/dashboard` — сводка для главной панели
